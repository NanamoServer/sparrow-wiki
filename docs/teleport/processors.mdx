---
title: 📍 Landing rules
---

Each feature defines how it chooses a landing position.

| Feature | Destination selection |
| --- | --- |
| Spawn, Home, Warp, offline teleport | Saved or configured coordinates. |
| TPA, patrol | The target player's position. |
| Back, DeathBack | Check the original coordinates, then search within 4 blocks horizontally and 8 blocks up or down. |
| RTP | Search randomly within the configured region; surface scanning in ordinary worlds, cavity scanning in ceiling dimensions such as the Nether. |
| World | Check the destination, then search within 8 blocks horizontally and 16 blocks up or down if needed. |

Safety searches check boundaries, collisions, support and hazardous blocks. Back, DeathBack and RTP reject water, leaf support and Nether-roof locations by default. World allows shallow water with the head above the surface.

For Back, DeathBack and World, `--unsafe` allows the original coordinates if the search fails. RTP ends without teleporting when it cannot find a safe location.

There is no general YAML processor list for changing these rules. Developers can combine search rules and processors through the [Teleport API](../api/teleport.mdx).
